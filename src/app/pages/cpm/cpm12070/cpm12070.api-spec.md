### 版面結構（由上到下）

1. **大標題列**：置中、灰底，內容為動態組字串，例如「2024各樓組顧客意見統計表」（同年同月顯示到月，跨年顯示完整日期區間）。
2. **三層式表頭**（彩色分層，同一層同色系用深淺區分部門/Team）：
   - **第 1 層（Dept）**：例如「營運部」（紅/粉色系，橫跨時尚Team、流行Team、休閒Team、生活Team、特販Team）、「餐飲Team」（黃色系，橫跨美食街、餐廳輕食）、「營運支援Team」（綠色系，橫跨保全、停管、義交、清潔、其他）。
   - **第 2 層（Team/樓層）**：時尚Team、流行Team、休閒Team、生活Team、特販Team、美食街、餐廳輕食、保全、停管、義交、清潔、其他。
   - **第 3 層（葉節點）**：依分支不同，深度在視覺上「靠右對齊」而非固定層級——
     - 零售樓層類（時尚/流行/休閒/生活Team）：葉節點是樓層/專櫃名稱，例如 1F、化妝品、2F、3F、親子娛樂、居家生活，**沒有**再往下細分。
     - 餐飲/支援類（美食街、餐廳輕食、保全、停管、義交、清潔）：葉節點是服務類別，例如服務、衛生問題、設備（不同單位細分項目不同：美食街/餐廳輕食是「服務、衛生問題」；保全/義交只有「服務」；停管/清潔是「服務、設備」）。
     - 特販Team 整欄全年皆空白（無資料，但欄位保留）。
3. **月資料列（1~12 月）**：每月兩列，「客訴」（黑字）、「表揚」（紅字），欄位對齊上述葉節點欄。
4. **年度總計區塊**：
   - 「總計」列：客訴/表揚，依葉節點欄逐欄加總。
   - 「總計客訴」「總計表揚」列：依 **Team** 合併（colspan）加總，不逐葉節點列出。
5. **備註列**：固定文字「1. 客訴件數字統計與表揚數據皆已包含未回覆數字統計。」

## 資料來源與階層算法

葉節點/Team/Dept 名稱**不是**直接存在資料表的固定欄位，而是由 `CPM12070Repository.getReportRawData()`（Dapper 原生 SQL，取代原本的 `SP_CPM12070Report`）即時算出：

- 資料來源：`CSS3006`（客訴/表揚明細，經 `SUGG_TYPE='0'/'1'`分客訴/表揚）→ JOIN `CSS1005`（責任單位主檔：`CLASS_ID/CLASS_CODE/ORG_ID/CLASS_NAME`）→ JOIN `SYS3100`（組織樹，自己/父/祖父三層自我 JOIN，不用遞迴）→ JOIN `SYS1000`（`SYS_Type='T211'` 服務類別代碼表：00=無,01=服務,02=衛生問題,03=設備）。
- **`CSS1005.CLASS_CODE = '00'`**（此單位不細分服務類別）：`葉節點 = ORG_ID自己的Org_Name`，`Team = ORG_ID的父層Org_Name`，`Dept = ORG_ID的祖父層Org_Name`。
- **`CSS1005.CLASS_CODE ≠ '00'`**（此單位要細分服務/衛生問題/設備）：`葉節點 = SYS1000.SYS_Name`（CodeName），`Team = ORG_ID自己的Org_Name`，`Dept = ORG_ID的父層Org_Name`。
- PDF 表頭欄位鍵值用 `CLASS_ID`（每一欄＝一個 `CSS1005.CLASS_ID`），不是 `OrgPath`。
